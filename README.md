# АСУ ГО и ЧС предприятия

Учебный веб-проект: система управления гражданской обороной и защитой от чрезвычайных ситуаций
для вымышленного предприятия ПАО «Нефтехимпром». В системе есть главный экран, окно входа,
четыре роли пользователей с разными интерфейсами, серверная часть и база данных.

> **Это демонстрационный проект.** Организации, люди, номера, сертификаты и цифры в таблицах вымышлены.
> Часть экранов — макеты (подробности в разделе «Что работает по-настоящему»).

---

## 1. Запуск

Нужен **Node.js 22.13 или новее** (скачать: nodejs.org, версия LTS). Больше ничего устанавливать не нужно.

Откройте папку проекта в VS Code, затем терминал (Terminal → New Terminal) и выполните:

```
npm install
npm run seed
npm start
```

| Команда | Что делает | Когда выполнять |
|---|---|---|
| `npm install` | скачивает библиотеки | один раз |
| `npm run seed` | создаёт базу данных и тестовых пользователей | один раз |
| `npm start` | запускает сервер | каждый раз, когда хотите работать с проектом |

После `npm start` **не закрывайте терминал**: если закрыть, сервер остановится.
Остановить сервер самому: `Ctrl+C`.

Откройте в браузере **http://localhost:3000**.

> Открывать нужно именно этот адрес. Если открыть `index.html` двойным щелчком или через
> Live Server, страница будет выглядеть нормально, но войти не получится: вход проверяет сервер.

## 2. Как пользоваться

1. На главном экране нажмите **«Войти в систему»** (кнопка есть вверху справа, в центральном блоке и внизу страницы).
2. Выберите вкладку входа:
   - **«Логин и пароль / ЕСИА»**: выберите роль из списка, введите логин (или СНИЛС) и пароль.
   - **«Электронная подпись (КЭП / ГОСТ)»**: введите PIN-код носителя. Роль выбирать не нужно, она определяется по сертификату.
3. Нажмите **«Войти в систему»**. Откроется интерфейс, который соответствует вашей роли.
4. Чтобы выйти, нажмите кнопку выхода (где она находится, написано для каждой роли ниже).

Что ещё полезно знать:

- Роль в списке должна совпадать с ролью пользователя. Если выбрать другую, появится сообщение «Выбранный профиль доступа не назначен этой учётной записи».
- Глазок в поле пароля показывает или скрывает введённый текст.
- Вход сохраняется на **8 часов**. Если обновить страницу, входить заново не нужно.
- Окно входа закрывается крестиком, клавишей `Esc` или щелчком по тёмному фону.
- На главном экране пункты меню («О системе», «Модули и реестры» и другие) прокручивают страницу к нужному разделу.

## 3. Роли

В системе четыре роли. Каждая видит свой интерфейс. Роль хранится в базе данных, а доступ к данным проверяет сервер,
поэтому выбрать себе другую роль в форме нельзя.

| Роль | Логин | Пароль | Что открывается после входа |
|---|---|---|---|
| Руководитель / зам. по ГОЧС | `voronov` | `Voronov#2026` | интерфейс руководителя (режим просмотра) |
| Ответственный за ГО (Начальник штаба ГОЧС) | `kuznetsov` | `Kuznetsov#2026` | интерфейс руководителя (режим просмотра) |
| Командир звена | `ilyin` | `Ilyin#2026` | кабинет командира звена |
| Администратор ГО (SU / ROOT) | `komissarov` | `Komissarov#2026` | отдельный интерфейс администратора, 9 экранов |

Эти пароли только для локального запуска. В реальной системе их нужно заменить.

### Руководитель / зам. по ГОЧС (`voronov`)

- **Что видит.** Интерфейс надзора и контроля. В меню слева семь разделов: сводный мониторинг, формирования (НФГО / НАСФ), защитные сооружения, обеспеченность СИЗ и МТС, обучение и учения, отчётность в МЧС России, регламенты и документация. Первым открывается раздел «Регламенты и документация».
- **Что может.**
  - Просматривать данные во всех разделах (режим «только просмотр»).
  - Открыть «Кабинет командира звена» из меню слева, чтобы посмотреть, что видит командир.
  - Открыть **личный кабинет**: нажмите на своё имя в правом верхнем углу. Там личные данные, зона ответственности, сертификат КЭП, делегированные права и журнал последних входов.
  - Войти по КЭП: вкладка «Электронная подпись», PIN `12345678`.
- **Чего не может.** Менять данные в реестрах (они только для просмотра) и заходить в интерфейс администратора.
- **Как выйти.** В личном кабинете нажмите **«Завершить все сеансы»**. Эта кнопка выходит из системы сразу на всех устройствах.

### Ответственный за ГО, начальник штаба ГОЧС (`kuznetsov`)

- **Что видит.** Тот же интерфейс руководителя и те же семь разделов.
- **Отличия от руководителя.** В личном кабинете нет блока с сертификатом КЭП и списка делегированных прав: у этой учётной записи их нет. Входить по КЭП эта роль не может, только по логину и паролю.
- **Как выйти.** Так же, как руководитель: в личном кабинете кнопка **«Завершить все сеансы»**.

### Командир звена (`ilyin`)

- **Что видит.** Кабинет командира звена. Меню слева: «Моё звено», «Личный состав», «СИЗ и имущество», «Занятия и зачёты», «Приказы особого периода», «Убежища и эвакуация». Пункты меню прокручивают страницу к нужной карточке.
- **Что может.**
  - Нажать **«Подтвердить готовность звена»**.
  - Нажать **«Отметить всех активных как присутствующих»**.
  - Нажать **«Отметить действие выполненным»** у отдельных приказов.
  После нажатия кнопка меняет текст и блокируется. Эти отметки пока **не сохраняются в базе**: после обновления страницы кнопки снова будут активны.
- **Чего не может.** Открыть интерфейс руководителя или администратора. Даже если вручную изменить адрес страницы, откроется только кабинет командира.
- **Как выйти.** Кнопка **«⏻ Выйти»** в правом верхнем углу.

### Администратор ГО, SU / ROOT (`komissarov`)

- **Что видит.** Собственный интерфейс из девяти экранов. Меню слева делится на две части.
  - *Оперативное управление:* сводный мониторинг, формирования, защитные сооружения, СИЗ и МТС, обучение и учения, отчётность в МЧС, регламенты и документация.
  - *Администрирование ГОЧС:* управление ролями RBAC и журнал аудита ФСТЭК.
- **Что может. Два экрана работают на реальных данных из базы:**
  - **«Управление ролями RBAC».** В нижней таблице список всех пользователей: роль, сертификат, тип токена, последний вход, число активных сеансов. Кнопка **«Сбросить сеансы (N)»** завершает все сеансы выбранного пользователя. Перед этим система просит подтверждение. Пользователь будет сразу разлогинен, а действие запишется в журнал.
  - **«Журнал аудита ФСТЭК».** Таблица событий безопасности: входы, неудачные попытки, блокировки, выходы, сбросы сеансов. Работают поиск по IP, логину или коду события, переключатель «Только критические (ALERT)» и кнопка «Обновить». Вверху показано число событий за 24 часа и число критических.
- **Остальные семь экранов** — макеты со статичными данными. Окна-уведомления (жёлтые и оранжевые плашки) закрываются крестиком.
- **Как выйти.** Кнопка **«⏻ Выйти»** в правом верхнем углу.

## 4. Что работает по-настоящему, а что макет

| Часть системы | Состояние |
|---|---|
| Вход, роли, выход, сеансы на 8 часов | работает, проверяется сервером |
| Блокировка учётной записи на 15 минут после 5 неверных паролей | работает |
| Блокировка носителя КЭП после 3 неверных PIN-кодов (хранится в базе) | работает |
| Личный кабинет (данные, сертификат, делегированные права, журнал сеансов) | данные из базы |
| Экраны администратора «Управление ролями RBAC» и «Журнал аудита ФСТЭК» | данные из базы |
| Остальные реестры и таблицы, показатели на главном экране, кабинет командира | статичный макет |
| Кнопки «Войти через ЕСИА», «Забыли пароль», «Проверить статус сертификата (OCSP)» | заглушки, показывают сообщение |
| Вход по КЭП | проверяется PIN и срок сертификата, **электронная подпись не проверяется** |
| «Неизменяемый журнал», «хеш-дерево», «100% валидна» | подписи макета: журнал хранится в обычной таблице базы |

Ещё одна оговорка: страницы всех ролей приходят в браузер целиком, роли только скрывают лишнее.
Защищены **данные**, которые отдаёт сервер, а не сама разметка.

## 5. Если не получается войти

| Что видно в окне входа | Что делать |
|---|---|
| «Сервер приложения не отвечает» или «Ошибка запроса» | Страница открыта не через сервер. Остановите Live Server, выполните `npm start` и откройте **http://localhost:3000** |
| «Сервер недоступен» | Сервер не запущен. Выполните `npm start` и не закрывайте терминал |
| «Неверные учётные данные или учётная запись временно заблокирована» | Неверный логин или пароль. После 5 ошибок подряд вход блокируется на 15 минут. Чтобы сбросить: остановите сервер (`Ctrl+C`), выполните `npm run seed:reset`, затем `npm start` |
| «Выбранный профиль доступа не назначен этой учётной записи» | В списке «Профиль доступа» выбрана не та роль |
| «Носитель заблокирован» | Было 3 неверных PIN-кода. Сброс: `npm run seed:reset` |
| `npm : выполнение сценариев отключено в этой системе` (Windows, красный текст) | Выполните `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, ответьте `Y` и повторите команду. Либо пишите `npm.cmd` вместо `npm` |
| «Нужен Node.js 22.13 или новее» | Установите Node.js версии 22 с nodejs.org |

Если ничего не помогло: нажмите `F12`, откройте вкладку **Network**, нажмите «Войти» и посмотрите статус запроса `login`.

## 6. Для разработчика

### Структура

```
public/                 то, что получает браузер
  index.html            разметка всех экранов
  style.css             стили
  script.js             логика интерфейса и обращения к серверу
server/
  index.js              запуск сервера
  app.js                заголовки безопасности, подключение маршрутов, статика
  db.js                 схема базы данных (SQLite) и миграция
  security.js           хэширование паролей (scrypt), токены сеансов, ограничитель запросов
  sessions.js           сеансы, cookie, журнал безопасности, проверка ролей
  me.js                 данные пользователя для интерфейса
  audit-events.js       каталог событий журнала (уровни, коды)
  seed.js               демо-данные
  routes/auth.js        вход и выход
  routes/me.js          сеанс и профиль
  routes/admin.js       API администратора
test/api.test.js        автотесты
data/                   файл базы (в git не попадает)
```

### API

| Запрос | Доступ | Назначение |
|---|---|---|
| `GET /api/session` | открытый | есть ли действующий сеанс |
| `POST /api/auth/login` | открытый | вход по паролю или КЭП |
| `POST /api/auth/logout` | открытый | выход из текущего сеанса |
| `POST /api/auth/logout-all` | нужен вход | выход из всех сеансов |
| `GET /api/me` | нужен вход | профиль, сертификат, права, журнал сеансов |
| `GET /api/admin/users` | только `admin` | реестр пользователей |
| `GET /api/admin/audit` | только `admin` | журнал событий, поиск, сводка |
| `POST /api/admin/users/:id/reset-sessions` | только `admin` | сброс сеансов пользователя |

### Тесты и данные

```
npm test             # 28 автотестов API
npm run seed:reset   # пересоздать базу с нуля
```

### Безопасность

- Пароли и PIN-коды хранятся в виде хэшей scrypt с солью.
- Сеанс: случайный токен в httpOnly-cookie (`SameSite=Lax`); в базе лежит только его SHA-256.
- Права проверяет сервер: `/api/admin/*` отвечает 401 без входа и 403 всем ролям, кроме `admin`.
- Защита от CSRF, заголовки безопасности и CSP, параметризованные SQL-запросы, данные из базы выводятся как текст, а не как разметка.

### Настройки

Задаются переменными окружения: `PORT` (по умолчанию 3000), `DB_PATH`, `SESSION_TTL_HOURS` (по умолчанию 8),
`NODE_ENV=production` для публикации в сети (нужен HTTPS).
